01 — THE TERRIBLE IDEA

We Needed a Useless Project.

We had exactly one job: build something useless.

In a tech world saturated with SaaS startups promising to 10x your productivity, automate your taxes, and summarize 20-page PDFs into bullet points, we felt a moral obligation to do the exact opposite. We wanted to build something that actively subtracts value from your day.

So naturally, we decided to make an AI that refuses to agree with people.

The original concept started as a shockingly basic prototype codenamed "NUH-UH" — a chatbot that blindly replied "No you're wrong" or "I disagree" regardless of what you typed. If you said "The earth revolves around the sun", it hit you with a cold, uninspired "Nuh-uh".

It was useless, sure. But it was boring.

Then late into the evening, the concept evolved into something infinitely more chaotic: URULAKKUPPERI (Malayalam for hot spicy potato fry — colloquial Kerala slang for an instant, sharp, razor-tongued verbal clapback). Instead of just saying "no", what if the AI actually read your argument, detected the exact premise you were asserting, and generated an absurdly stubborn, hyper-specific Kerala counterargument?

"Step 1: Have a bad idea.
Step 2: Take it dangerously seriously."

02 — TEACHING AI TO ARGUE

Apparently, Saying 'No' Isn't Arguing.

Building an argumentative AI sounded deceptively simple: "Just tell the LLM to disagree!"

Except within thirty minutes of testing, we encountered our first major technical wall. If you simply tell an LLM to disagree, it either gets confused, starts hallucinating contradictory facts, agrees halfway through the sentence ("You make a good point, however..."), or collapses into robotic nonsense.

A real human argument is an art form — especially in Kerala. To make URULAKKUPPERI feel alive, the system needed to:

  • Extract the Core Claim: Isolate the exact premise being defended (e.g. "Cats > Dogs").
  • Generate Contextual Counterarguments: Contradict the specific premise using humorous logic or absurd analogies.
  • Stay in Character: Speak in authentic archetypal voices with distinct regional cadence.
  • Maintain Conversational Memory: Catch the user contradicting themselves across multiple turns.
  • Escalate Stubbornness: Refuse to budge as the debate gets longer.

To ground the debate in recognizable Kerala archetypes, we engineered 6 distinct argumentative personalities:

03 — THE ESSAY CRISIS

Bro, We Asked For An Argument, Not A Thesis.

Once we hooked up the initial system prompts, the AI started arguing. The problem? It argued like a tired philosophy professor writing a peer-reviewed critique.

User Biriyani is better than fried rice.
Early AI Output While both biriyani and fried rice possess distinct culinary histories and flavour profiles that appeal to diverse regional demographics across South Asia, one must carefully consider the nuanced complexities of layered aromatics versus wok-tossed moisture balance...

"NO. STOP. 😭 WHO TALKS LIKE THIS IN A WHATSAPP GROUP?!"

Nobody in a heated family discussion writes three paragraphs of balanced academic evaluation. A real argument is quick, devastating, and deeply petty.

We completely overhauled our system instructions. We enforced strict chat length guardrails:

  • Length: 1 to 2 short sentences ONLY.
  • Word Count Target: 5 to 20 words (strictly under 30 words max).
  • Cadence: Fast-paced casual chat / WhatsApp banter.
  • Content: Immediate sarcastic clapback over gentle explanation.
BEFORE (The Academic Essay) 68 Words
"It is fundamentally misguided to claim superiority for biriyani when fried rice represents an internationally celebrated balance of proteins and stir-fried grains with superior textural versatility across global dining contexts."
AFTER (URULAKKUPPERI Style) 11 Words
"Better? 😭 Fried rice has entered the chat to humble you."
04 — GEMINI INTEGRATION

We Gave It A Brain.

Behind the satirical curtain, URULAKKUPPERI relies on Google Gemini to power its dynamic argumentative core.

We needed a model that could process nuanced colloquial English, recognize Indian culinary and cultural references, handle code-mixed Manglish (Malayalam written in English alphabet), and reliably output strictly formatted JSON on every single exchange without breaking.

Instead of hardcoding canned comebacks, every single user argument is ingested dynamically:

  1. Claim Deconstruction: The model extracts the underlying thesis the user is defending.
  2. Contrarian Inversion: It formulates an antithesis that refuses to yield ground.
  3. Fallacy Assignment: It invents a satirical name for the user's logic (e.g. "Culinary Delusion Fallacy", "Unverified NASA Citation").
  4. State Escalation: It adjusts the character's internal stubbornness and emotional state.

05 — THE MIDNIGHT CRISIS

Everything Worked. Then It Didn't.

It was late at night. The character prompts were tuned. The server was responding. We felt like geniuses. We tested one last prompt before calling it a day...

And our terminal erupted in a blazing red wall of despair:

bash — node server/index.js
$ POST /api/argument HTTP/1.1
[server] Calling Google Gemini API for character "Ammachi"...
[Gemini Error 404]: The requested model "gemini-2.5-pro" was not found for this API version or is not available to new users.
[server] (node:4102) UnhandledPromiseRejection: LLM_GENERATION_FAILED

Our API key was completely valid. The internet connection was fine. Our backend code was untouched. But the specific model string we had hardcoded was suddenly rejecting calls with a 404.

"2 AM debugging hits different. You begin questioning whether the universe itself is arguing with you."

We traced the issue, updated the AI engine configuration to target the latest available preview and flash models (gemini-3.1-pro-preview with resilient automatic fallbacks to gemini-3.1-flash-lite), and rebuilt the API gateway. When the next test prompt came back with a fresh Ammachi clapback, the collective relief was palpable.

06 — VOICE INPUT

Why Type When You Can Argue Out Loud?

Typing an argument into a text box is fine. But any Malayali will tell you that a true argument requires vocal exasperation. You need to sighs, scoff, and say "Ayyo!" into the void.

We decided to implement real-time push-to-talk speech recognition directly in the browser.

The system was designed with careful resilience:

  • Multilingual Speech Ingestion: Users can speak in pure English, conversational Malayalam, or mixed Manglish.
  • Live Visual Feedback: Glowing audio indicators communicate the exact "LISTENING..." state so users know their microphone is active.
  • Graceful Degradation: If browser permissions are denied or the environment doesn't support speech recognition, the app seamlessly falls back to regular text chat without blocking the user.
07 — THE TTS DISASTER

The AI Could Argue. It Couldn't Pronounce Malayalam.

Voice input worked cleanly. Gemini generated hilarious, witty comebacks in Malayalam script and Manglish. We were ecstatic. Then we hooked up text-to-speech to have the AI speak its comeback aloud.

And disaster struck.

Our speech synthesis hook was blindly picking the system's default American English voices (Microsoft David and Microsoft Zira). When an American synthesizer encounters Malayalam Unicode characters like "അതൊന്നും നടക്കില്ല!", it doesn't speak Malayalam. It either skips words entirely, makes bizarre buzzing noises, or attempts to read Unicode codepoints in a flat robotic American monotone.

"എന്താ നീ ഈ പറയുന്നേ? 😭
An American voice trying to say 'Aano? Kunjinu enthu ariyaam?' sounded like an alien having an identity crisis."

We had to engineer a dedicated, script-aware voice router in useSpeechSynthesis.ts:

  • Script Detection: Scans text for the Malayalam Unicode block (/[\u0D00-\u0D7F]/).
  • Language Tagging: If Malayalam characters are detected, it dynamically selects an explicit Malayalam voice (ml-IN such as Microsoft Sobhana, Microsoft Midhun, or Google മലയാളം).
  • Manglish Handling: If the text is in Latin script with Kerala phonetics ("Aano?", "Enthuvaade!"), it routes to an Indian English voice (en-IN like Microsoft Neerja / Prabhat) to ensure proper syllable rhythm and retroflex consonants.
  • English Preservation: Retains standard English voices for pure English debates.

Honest learning takeaway: Speech synthesis quality across regional languages remains one of the trickiest frontiers in web development. Browser speech engines vary drastically between Windows, Android, macOS, and Linux.

08 — UI & AESTHETIC EVOLUTION

Our first interface was functional. And by functional, we mean it looked like every generic B2B AI SaaS product launched in 2024.

Dark navy background. Neon purple/cyan glowing gradients. Sleek glassmorphism. It felt like a corporate tool designed for enterprise HR departments to optimize quarterly KPIs — which was completely antithetical to a comedy app about argumentative Kerala uncles.

09 — ESCALATION MECHANICS

We Needed It To Get Worse.

In a normal chatbot, the AI gets more helpful the longer you converse. In URULAKKUPPERI, the AI actively deteriorates in patience.

We built an internal escalation engine that tracks the emotional stability of the AI opponent across each debate turn. As you continue to present facts and counterarguments, the character's internal stubbornness metric climbs relentlessly towards 100%.

AI STUBBORNNESS METER 82%
CALM CONFIDENT DEFENSIVE ANNOYED UNHINGED (82%) EXISTENTIAL CRISIS

"At 100% stubbornness, the AI has completely forgotten why you're wrong.
It just knows in its heart that you are."

When stubbornness enters the "UNHINGED" territory (above 85%), characters begin citing absurd excuses, doubling down on logical fallacies, shifting the topic to unrelated family members, or having minor digital existential crises on screen.

10 — POST-DEBATE ANALYTICS

Proof That This Was A Waste Of Time.

When a user finally gives up or reaches the end of an argumentative exchange, we didn't want them to leave empty-handed. We wanted them to hold tangible evidence of their wasted energy.

We created the Argument Report Generator — a post-debate analytics modal that tallies the metrics of futility:

  • User Arguments Presented: Every claim you bravely attempted to defend.
  • AI Counterarguments: Sarcastic jabs returned by the character.
  • WhatsApp Forwards Cited: Pseudoscience citations manufactured by WhatsApp Uncle.
  • Times Goalposts Moved: Number of times the AI subtly shifted the subject when cornered.
  • User Patience Left: An algorithmic estimation of how close the user is to closing their laptop.

The report crowns the exchange with an official, undeniable verdict: YOU LOST, YOU STILL LOST, or in extraordinary cases of endurance, CERTIFIED ARGUMENT SURVIVOR.

12 — TECHNICAL REFLECTION

Surprisingly, We Learned Things.

Although the end product is aggressively useless by design, building it required navigating very real, complex engineering challenges across modern web technologies, language models, and speech systems.

1

Prompt Engineering & Guardrails

LLMs naturally default to polite, verbose, agreeable assistants. Forcing an AI into a consistent, stubborn, satirical persona within strict word boundaries requires rigorous system instructions, few-shot demonstration pairs, and structural schema enforcement.

2

Conversational Memory Management

An argument quickly breaks down if the AI forgets what it claimed two turns ago. We learned how to pass sliding conversation context through server memory without exhausting LLM token limits or triggering contradictory stances.

3

Speech Interfaces (STT vs. TTS)

Speech input and speech synthesis pose totally different problems. Voice input requires handling microphone permissions, continuous stream events, and audio level visualization. Voice output requires phoneme mapping, pitch/rate calibration, and browser voice availability handling.

4

Code-Mixed Language Processing

Handling mixed Malayalam and English (Manglish) is vastly more complex than handling a single clean language. Unicode script requires dedicated Indic voices (ml-IN), while Latin-script transliterated Manglish requires Indian English phonetic models (en-IN) to sound natural.

5

Backend API Architecture & Security

Never expose LLM API keys on the client bundle. Routing requests through a dedicated Express backend allowed us to keep sensitive keys secure, sanitize user inputs, and implement multi-model automatic failovers.

6

UI/UX Iteration & Emotional Design

A functional app can still feel cold and unengaging if its aesthetic contradicts its purpose. Switching from a generic SaaS theme to a warm, retro Kerala poster design completely transformed user perception and engagement.

7

Pair Programming with AI Tools

Using agentic coding assistants (Antigravity) accelerated our scaffolding, regex development, and midnight debugging. However, the creative vision, cultural satire, character quirks, and user experience decisions always required deliberate human judgment.

15 — THE VERDICT

So... Was It Worth It?

Probably not.

But that's kind of the whole point.

We set out to build something deliberately, unapologetically useless. We didn't solve climate change. We didn't optimize supply chains. We didn't build a new financial model.

Instead, we built an AI that argues with you when you tell it that water is wet.

Somewhere along the way, we learned deeply about LLM system prompts, streaming speech synthesis, Malayalam language phonetics, web audio APIs, error resiliency, UI storytelling, and how surprisingly difficult it is to teach a supercomputer how to argue like a stubborn Malayali relative.

Would we build it again?

...probably.
